00Shipped today

The project is a flat, square, full-bleed label. The group directly under it is a rounded, bordered card inset 8px per side. Two different visual languages, one tree.

nowRounded inset card

The 8px side margin plus the 1px border push a grouped row's content to 21px while an ungrouped row starts at 12px, and cost the same again on the right — on top of the row's own 12px padding and the list's 8px gutter.

01What marks a group once the rounded box is gone

Same data in all three. The question is whether containment still reads without a rounded card, and what it costs in width.

ALeft rail + flat header

Group header becomes a flat full-bleed sub-label. Members get a 2px vertical accent line in the branch colour and an 8px indent. Strongest containment read of the three; the indent is now deliberate rather than an accident of borders.

  • Reads as a tree, matching the flat project label.
  • Right edge fully reclaimed.
  • Rows still indent 8px, so the left is only half reclaimed.
  • Group colour moves from the right bar to the rail; per-row colour bars come back.

BHeader only, no indent

Flat sub-header, rows flush with ungrouped rows, a hairline rule closing the group. Maximum width reclaimed on both edges — grouping is carried by the header plus the shared colour bar on the right.

  • Grouped and ungrouped rows start at the same x. Nothing wasted.
  • Weakest containment: where the group ends rests entirely on one hairline.
  • Furthest from components.md's "the one box in the tree".

CSquare full-bleed boxyour pick

Keep the box, drop border-radius and the side margins; top and bottom hairlines only, running edge to edge with a slightly raised ground. Smallest diff, still unmistakably a container.

  • Containment as strong as today; no rounding to clash with the square project label.
  • Both edges reclaimed — rows line up with ungrouped rows.
  • Raised ground does the work the side borders used to.

02How far the side trim goes

Both frames use option C. The only difference is whether the row's own padding is touched. The long window title on row 2 is the thing that gets more or less room — it is the line that tells two sessions on one worktree apart.

What "tighten every row" actually changes: row side padding 12px → 8px and the list's right gutter 8px → 4px. Measured on this page, that is +12px of title per row — the row moves 4px left and the title's right edge gains the 4px of padding plus the 4px of gutter. It also moves every ungrouped row and the project label, so it needs a browser pass against all three density presets.

1Group inset only

Fix only the inset the group adds. Row padding, list gutter and the project label are untouched — nothing outside a group moves a pixel.

  • Blast radius is one CSS block; the density presets cannot be affected.
  • If 12px still feels airy to you, this does not address it.

2Also tighten every row

On top of option 1: row padding to 8px, list gutter to 4px, project label to 8px. Every row in the sidebar gains width, grouped or not.

  • The whole sidebar gets tighter, not just groups.
  • Touches the sidebar's rhythm — needs a real-browser check at normal/tight/compact.
  • 4px gutter is the colour-bar hit target's clearance from the resizer; needs verifying, not assuming.
