State iconography

Decision: I2 SVG line family for everything, but state icons use the I3 geometric shapes (▶ ◆ ◌ ■ ✗) drawn as SVG — no metaphor icons for states.

One icon vocabulary used everywhere a session appears: sidebar row, minimized chip, grid tile header. Five states from the code — starting, running, attention (waiting on you), exited, exited with error — plus the worktree mark and toolbar actions. The subtitle line is always the window title; state lives only in the icon + colour.

I1Geometric dots

Shape encodes state (circle = alive, ring-spinner = starting, square = exited), colour reinforces it. Attention pulses. Wins: tiny, quiet, reads at 8px, one CSS file, zero assets, works in the terminal-first preset too. Loses: abstract — a new user has to learn square = exited; toolbar actions still need a separate icon source.

I2Line icons (Lucide-style SVG)

A small inline SVG set (≈12 icons: play, bell, loader, square, alert, minus, rotate, x, grid, git-branch, plus, chevron). Same stroke weight everywhere; colour from tokens. Wins: self-explanatory, matches the "dev-tool" identity, actions and states come from one family so the whole UI reads as one hand. Loses: busiest at 40px row height; needs an icon sprite (~2KB) and a rule that nobody adds a stray unicode glyph again.

Actions (same family)

I3Monospace glyphs

Text characters from JetBrains Mono only: ▶ running, ◆ attention, ◌ starting, ■ exited, ✗ error. Actions stay text too. Wins: zero assets, terminal-native feel, copy-pastes into logs. Loses: glyph coverage varies by platform font fallback (Windows especially), optical sizes differ between characters so alignment is fiddly — the problem the current UI already has.
